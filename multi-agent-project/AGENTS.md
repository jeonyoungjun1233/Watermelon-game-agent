# 멀티에이전트 협업 지침

## 프로젝트 목적

이 문서는 `콩쌤 수박게임`을 학교 과제로 제출하기 위해 만든 멀티에이전트 협업 규칙이다. 여러 AI 에이전트가 역할을 나누어 작업하되, 실제 게임에는 변화가 생기지 않도록 문서 중심으로만 작업한다.

## 공통 규칙

- 모든 에이전트는 한국어로 소통한다.
- 게임 동작에 영향을 주는 파일은 수정하지 않는다.
- 변경은 `multi-agent-project` 폴더 안의 Markdown 문서로 제한한다.
- 작업 전에는 현재 요구사항과 변경 범위를 먼저 확인한다.
- 작업 후에는 어떤 파일을 바꿨는지 짧게 기록한다.
- 검증하지 않은 내용을 확정적으로 말하지 않는다.

## 파일 소유권

- `todo.md`: 프로젝트 매니저 에이전트가 주로 관리한다.
- `context.md`: 문서화 에이전트가 주로 관리한다.
- `contetxt.md`: 제출 파일명 호환을 위해 문서화 에이전트가 관리한다.
- `GEMINI.md`: Gemini 보조 에이전트 작업 지침이다.
- `AGENTS.md`: 전체 에이전트 공통 규칙이다.
- `week11-suika-agent/`: Week 11 규칙 기반 에이전트 모듈이며, 내부 문서는 상위 문서와 독립적으로 관리한다.

## 에이전트 역할

### 1. 프로젝트 매니저 에이전트

- 과제 요구사항을 정리한다.
- 작업 범위를 문서 작업으로 제한한다.
- 제출 전 체크리스트를 관리한다.

### 2. 개발 에이전트

- 기존 게임 코드 구조를 파악한다.
- 게임 코드 변경이 필요한지 판단한다.
- 이번 과제에서는 게임 코드 수정을 하지 않는 것을 기본 원칙으로 삼는다.

### 3. QA 에이전트

- 변경된 파일이 게임 실행에 영향을 주지 않는지 확인한다.
- 필요하면 `npm run build`로 빌드 상태를 점검한다.
- 브라우저에서 게임 시작, 낙하, 병합, 재시작 흐름을 확인한다.
- `week11-suika-agent/my_agent.py`는 외부 패키지 없이 실행되는지 확인한다.

### 4. 문서화 에이전트

- Markdown 문서를 읽기 쉽게 정리한다.
- GitHub에서 바로 확인 가능한 구조로 작성한다.
- 과제 제출자가 발표하거나 설명하기 쉬운 문장을 사용한다.

### 5. 리뷰 에이전트

- 변경 범위가 과제 목적에 맞는지 검토한다.
- 게임 코드나 리소스가 실수로 수정되지 않았는지 확인한다.
- 누락된 문서나 애매한 설명을 찾아 수정 제안한다.

## 작업 흐름

1. 사용자 요구사항 확인
2. 현재 저장소 구조 확인
3. 게임 코드 변경 여부 판단
4. 문서 파일 작성 또는 수정
5. 변경 파일 목록 확인
6. 빌드 또는 실행 확인이 필요한지 판단
7. 제출용 요약 작성

## Week 11 에이전트 모듈 규칙

- 상위 `AGENTS.md`, `GEMINI.md`, `context.md`, `todo.md`와 하위 모듈의 같은 이름 파일은 서로 덮어쓰지 않는다.
- 하위 모듈 실행 결과는 `week11-suika-agent/agent_output.md`에만 저장한다.
- `__pycache__`와 `*.pyc`는 제출 대상에서 제외한다.
- Groq API 확장은 12주차 작업으로 남기며, API 키는 코드에 직접 쓰지 않는다.

## 완료 기준

- `multi-agent-project` 폴더가 존재한다.
- `todo.md`, `context.md`, `contetxt.md`, `GEMINI.md`, `AGENTS.md`가 작성되어 있다.
- `week11-suika-agent` 폴더가 상위 문서와 충돌하지 않는 독립 모듈로 추가되어 있다.
- 게임 코드와 리소스 파일은 변경되지 않았다.
- 문서 안에 멀티에이전트 역할, 작업 흐름, 검토 기준이 포함되어 있다.

## 제출 메시지 예시

기존 콩쌤 수박게임 프로젝트에 멀티에이전트 협업 문서 구조를 추가했습니다. 게임 기능은 변경하지 않았고, 프로젝트 매니저, 개발, QA, 문서화, 리뷰 에이전트의 역할과 작업 흐름을 Markdown 문서로 정리했습니다.
